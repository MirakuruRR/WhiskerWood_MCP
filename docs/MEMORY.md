# Общая база знаний

Половина работы над модом — это выяснение того, что в игре не работает. Какая подсистема
оказалась тупиком, какая идиома UE4SS здесь ломается, почему хук пришлось вешать именно
сюда. Из кода это не выводится, и каждый моддер выясняет заново.

Поэтому база едет вместе с репозиторием: `data/memory-seed.jsonl`, 396 записей, собранных
за время работы над семью модами. При первом `bun run setup` она вливается в вашу
локальную память, дальше доступна через `ww_memory_search` и `ww_memory_wakeup`.

База на русском. Идентификаторы, теги и пути хуков языконезависимы, поиск работает по ним,
ассистенты читают русский без проблем. Записи на английском приветствуются.

## Как получать обновления

```bash
git pull
bun run memory:sync
```

Печатает `+N новых, ~M обновлено, K без изменений`. Ваши собственные записи не трогаются
никогда.

## Как это устроено

Обычный трёхсторонний мёрж, как в git. «Их» — сид из репозитория, «наше» — ваша база,
база слияния — та ревизия сида, которую вы применили в прошлый раз. Каждая запись хранит
`origin` (`seed` или `local`) и `seed_hash` — отпечаток содержимого на момент последней
синхронизации.

| Ситуация | Что происходит |
|---|---|
| Записи у вас нет | Добавляется, `origin='seed'` |
| Апстрим не двигался | Пропуск |
| Вы её не трогали | Fast-forward на новую версию |
| Правили и вы, и апстрим | **Конфликт**: остаётся ваше, запись попадает в отчёт |
| Совпадает дословно | Усыновляется как `seed` — это та же запись, а не коллизия |

Конфликты не молчат: ревизия сида не отмечается применённой, пока они не разобраны.
Посмотреть, что предлагает апстрим, — `bun run memory:sync --dry-run`. Принять их версию —
`--prefer-seed`.

**Удалений в сиде нет.** Опровергнутое патчем приходит как `status: invalidated` с
причиной — так же, как это делает `ww_memory_invalidate`. Знание не исчезает, а получает
пометку «больше не верно», и видно, почему.

## Как отдать своё

```bash
bun run memory:export --local-only
```

Пишет `data/memory-seed.jsonl` только из ваших записей. Личные пути при экспорте
заменяются плейсхолдерами (`{gameDir}`, `{mcpRepo}`, `{modsRepo}`, `{home}`) — ни домашний
каталог, ни раскладка ваших дисков наружу не уедут. Приложите файл к пулл-реквесту.

Записи, которые не должны уезжать целиком, перечисляются в `data/memory-seed.exclude.txt`
(id и причина в строке).

## Что стоит записывать

Не то, что видно в коде, а то, что стоило времени:

- **decision** — почему выбран этот хук или эта подсистема, а не очевидная альтернатива
- **pitfall** — потраченная впустую попытка, с тегом-идентификатором: он станет триггером
  линта в `ww_validate_mod`
- **note** — устройство подсистемы, которое пришлось раскапывать
- **todo** — непроверенное, чтобы следующий не считал это фактом

Пример хорошей записи — из тех, что уже в базе: «LocTextBlock перечитывает свой Key при
сборке Slate и затирает SetText поверх него; лечится не задержкой, а `SetKey(FName)`».
Такое не выводится ниоткуда и стоило нескольких часов.
