# Разворачивание

Ручной путь. В Claude Code то же самое делает скилл `/ww-setup` — он сам гоняет команды,
читает вывод и ведёт через ручные шаги.

Сверяться на любом этапе: `bun run doctor`. Он печатает состояние всех проверок и
следующую команду для каждой незакрытой.

## 0. Тулчейн

```bash
bun --version            # 1.3+
python --version         # 3.x
dotnet --list-sdks       # нужна строка, начинающаяся с 10.
```

Python нужен ровно для `wwpak.py`, который вынимает `AssetRegistry.bin` из пака.
.NET SDK — для сайдкара `WwParse` на CUE4Parse, он читает таблицы данных по `.usmap`.
Без них индекс соберётся только частично или не соберётся вовсе.

## 1. UE4SS

Нужна сборка [`experimental-latest`](https://github.com/UE4SS-RE/RE-UE4SS/releases/tag/experimental-latest)
— в стабильном 3.0.1 нет поддержки UE 5.6 и новее. Распакуйте в `<игра>/Whiskerwood/Binaries/Win64`
так, чтобы рядом с `Whiskerwood-Win64-Shipping.exe` оказался `dwmapi.dll`, а рядом — каталог
`ue4ss/`.

### Сигнатура StaticConstructObject_Internal

Без неё игра с UE4SS не запустится: резолвер падает на скане, `Fatal Error: PS scan timed
out`. Это [баг](https://github.com/UE4SS-RE/RE-UE4SS/issues/1248) апстрима, ломающий все
игры на UE 5.6+; правки исходников UE4SS не требует — есть штатный обход через свой AOB.

Создайте `ue4ss/UE4SS_Signatures/StaticConstructObject.lua`:

```lua
function Register()
    return "48 89 5C 24 10 48 89 6C 24 18 56 57 41 54 41 56 41 57 48 81 EC ? ? ? ? 48 8B 05 ? ? ? ? 48 33 C4 48 89 84 24 ? ? ? ? 48 8B 29 33 DB 4C 8B 79 08"
end

function OnMatchFound(MatchAddress)
    return MatchAddress
end
```

Маска снята с 0.7.208.0 (UE 5.8) и переживает мелкие патчи игры. Если после крупного
обновления (смена версии движка — как 5.6 → 5.8) скан снова начал
падать — функция ищется детерминированным обходом по указателям (частотная эвристика не
работает: вызовов «всего» порядка тысячи, в топ функция не попадает):

1. UE хранит на класс статическую таблицу пар `{const char* Name, FNativeFuncPtr}` для
   `StaticRegisterNatives`. Строка `SpawnObject` в exe ровно одна.
2. Найти указатель на неё в `.rdata` — соседний qword есть `execSpawnObject`.
3. `UGameplayStatics::SpawnObject` либо отдельная функция, которую `execSpawnObject` зовёт
   в хвосте (на 5.6), либо встроена в него целиком (на 5.8).
4. Хвост `SpawnObject` — сборка `FStaticConstructObjectParameters` на стеке: вызов
   конструктора `(rcx=&Params, rdx=Class)`, затем `Outer` в `Params+0x8`, `Name` в
   `Params+0x10`, флаги `0x1000000` в `Params+0x18`, и сразу за этим искомый вызов с
   `lea rcx,[Params]`.

Проверки, что нашли именно её: все call-сайты предварены `lea rcx,[rsp+..]` (структура по
ссылке), вызывающих функций сотни, в прологе читаются `[rcx]` (Class), `[rcx+0x8]` (Outer), `[rcx+0x18]` (флаги) и
`[rcx+0x70]`, а маска с вайлдкардами даёт одно совпадение на весь файл. Мастер-шаблон
ищется вне игры: capstone по exe, без запуска.

Запустите игру один раз и закройте. Должен появиться `ue4ss/UE4SS.log` — по нему
определяется версия UE4SS, и без него часть проверок работать не будет. В логе должна быть
строка `StaticConstructObject_Internal address: 0x... <- Lua Script` и ни одного
`Scan failed`.

## 2. Конфигурация

```bash
cp wwmcp.config.example.json wwmcp.config.json
```

`doctor` находит игру через Steam (AppID 2489330, реестр + `libraryfolders.vdf`), так что
в большинстве случаев править нечего. Если копия не из Steam или библиотек несколько —
поправьте `gameDir`. Остальные пути раскрываются из него шаблонами `{gameDir}`.

`modsRepo` — каталог, где вы держите моды, по умолчанию `../WhiskerWood_Mods`. Если его нет,
он создастся сам; библиотека `ww.*` приезжает из `data/lib/` этого репозитория.

`kitDir` — корень мод-кита Whiskerwood (каталог с `.uproject`), нужен только для модов на
Loom; см. раздел 6. Движок указывать не надо: он находится по `EngineAssociation` из
`<кит>/Whiskerwood.uproject` через реестр, а `engineDir` — ручной override на случай, когда
сборка движка лежит не там, где записано в реестре.

## 3. Мост и AutoDump

```bash
bun run bridge:deploy
```

Разворачивает в `ue4ss/Mods` три вещи и правит `mods.txt`:

- **WWBridge** — канал между сервером и игрой, включается сразу (`WWBridge : 1`);
- **AutoDump** — снимает дампы рефлексии, ставится **выключенным** (`AutoDump : 0`), потому
  что нужен только при переиндексации, а работает долго;
- **ww.\*** — библиотека рантайма, линкуется в `Mods/shared`, откуда её видит `require`
  любого мода.

## 4. Дампы

В Claude Code это делает `/ww-setup` (или `/ww-update-index` при переиндексации) через
инструмент `ww_capture_dumps` — здесь ручной путь для всех остальных случаев.

1. В `ue4ss/Mods/mods.txt` поставьте `AutoDump : 1`.
2. Запустите игру и **зайдите в сохранение**, не оставайтесь в главном меню.
3. Ждите ~60 секунд, пока в `ue4ss/UE4SS.log` не появится
   `ALL DONE captured_at=in_level`.
4. Закройте игру и верните `AutoDump : 0`.

```bash
bun run dumps:pull
```

Почему именно из сохранения: блюпринтовые классы подгружаются вместе с картой. Дамп из
главного меню соберётся без ошибок, но половина UI-классов в него не попадёт, и хуки на
них потом не найдутся.

## 5. Сборка индекса

```bash
bun run setup
```

Считает отпечаток игры, собирает индекс рефлексии, запускает сайдкар за таблицами и
локализацией, прогоняет приёмочные проверки и атомарно публикует профиль в
`dist/games/whiskerwood-<версия>/`. Заодно вливает общую базу знаний.

Сборка отказывается идти, если дампы старше пака: `.usmap` от прошлой версии ломает разбор
молча — таблицы с изменившимся layout отдают ноль строк без единой ошибки. Обойти
осознанно можно флагом `--allow-stale-dumps`.

## 6. Loom-режим

Loom — текстовый язык, который компилируется в обычные Blueprint-ассеты, а мод собирается в
`.pak`; игроку UE4SS не нужен. Этому режиму нужен **мод-кит** (репозиторий
`Whiskerwood-Project`, ветка 5.8), собранный **движок** под него и **`loom.exe`** из плагина
кита. Всё это приходит с китом: `loom.exe` лежит в
`<кит>/Plugins/LoomEditor/Binaries/ThirdParty/Loom/Win64/`, движок раскатывается отдельно
(его корень кит помнит в `EngineAssociation`).

Включается одним ключом — путём к киту:

```json
"kitDir": "D:/Whiskerwood/Whiskerwood-Project"
```

Проверка — `bun run doctor`, секция Loom: что нашлось, каким способом найден движок
(реестр или `engineDir`), не отстал ли `types.json` от пака игры, открыт ли редактор. Без
`kitDir` инструменты Loom отвечают `kit_not_configured` — это не поломка стенда:
инструменты рефлексии, живой игры и памяти работают как обычно.

Что даёт Loom-режим: `ww_loom_status` (кит, версии, отчёт последней сборки), `ww_lift`
(логика игрового Blueprint на языке мода), `ww_event_surface` (что подписать и что
переопределить вместо хука), `ww_loom_new_mod` (новый мод с PAL, `.uplugin` и заготовками без
интерфейса редактора; нужен закрытый редактор и `PythonScriptPlugin` в движке — он включается
только на этот запуск, `.uproject` не меняется), `ww_loom_validate` (check плюс правила
игры), `ww_loom_build` (сборка Blueprint), `ww_loom_install` (cook и `.pak` в `<saved>/mods`). Ответы
`ww_get_function`, `ww_get_type`, `ww_find_symbol` и `ww_search_members` получают
Blueprint-поля: `bp` (достижимо ли из Blueprint), `loom_call` — готовый вызов для исходника.
Полный цикл описан промптом `ww:new-loom-mod`, перенос готового Lua-мода — `ww:port-to-loom`.

Заготовки исходников лежат в `data/templates/loom/`: `BP_Startup` (DataTable и опции мода),
`BP_MapLoad`, `BP_MainMenuLoad`, `WBP_Overlay` с `HudOverlay` (оверлей в ряду HUD). Сервер
отдаёт их MCP-ресурсами `ww://templates/loom/<имя>`, когда включена группа `loom`. Файлы
`.lm` пишите **без BOM**: Loom отказывается разбирать файл с ним (`unexpected character`) —
это первое, на что смотреть, когда чужой редактор «сломал» рабочий исходник.

### Наборы инструментов

`toolsets` в конфиге решает, какие группы регистрировать: `recon` (индекс и разведка),
`live` (живая игра через мост), `lua` (моды UE4SS: скаффолд, хуки, валидация, установка),
`memory` (проектная память), `loom` (кит и Blueprint). По умолчанию включены все. В
Loom-режиме набор `lua` выключают — он к Loom-пайплайну не относится, и из 43 инструментов
остаётся 37:

```json
"toolsets": ["recon", "live", "memory", "loom"]
```

`ww_lua_api` и `ww_verify_hook` остаются: они входят в `recon`, и без них не обойтись при
разведке через `ww_game_eval` и трассировку. Что именно выключилось, видно по `bun run doctor`
и по списку инструментов, который печатает `bun run smoke`.

## 7. Подключение MCP

В Claude Code репозиторий уже содержит `.mcp.json` — сервер подхватится при открытии
проекта. Перезапустите клиент, чтобы он увидел сервер.

Этого мало для работы с китом: `.mcp.json` действует только в сессии, открытой в этом
репозитории, а путь в нём относительный. Чтобы сервер видели все сессии — и открытая в
ките, и в репозитории модов, — зарегистрируйте его на пользовательском уровне: в
`~/.claude.json` (`%USERPROFILE%\.claude.json`) в `mcpServers`, рядом с `loom`, с
**абсолютными** путями и переменной `WWMCP_CONFIG` (без неё сервер ищет `wwmcp.config.json`
в текущем каталоге сессии):

```json
"whiskerwood": {
  "type": "stdio",
  "command": "C:/Users/<пользователь>/.bun/bin/bun.exe",
  "args": ["run", "D:/path/to/WhiskerWood_MCP/src/stdio.ts"],
  "env": { "WWMCP_CONFIG": "D:/path/to/WhiskerWood_MCP/wwmcp.config.json" }
}
```

Это тот же фрагмент, что и в `.mcp.json` ниже, но с абсолютным путём к `bun.exe` (`where bun`)
и к конфигу. Файл — обычный JSON: лишняя запятая ломает клиенту весь список серверов. Без
ручной правки то же делает `claude mcp add-json --scope user whiskerwood '<фрагмент>'`, а
проверка — `claude mcp list` из каталога кита.
После правки **перезапустите клиент** — `~/.claude.json` читается один раз при старте, — и
проверьте `/mcp`: там должны быть и `whiskerwood`, и `loom`.

Чтобы пользоваться инструментами **из репозитория модов**, положите такой же `.mcp.json`
рядом с модами, прописав абсолютные пути:

```json
{
  "mcpServers": {
    "whiskerwood": {
      "command": "bun",
      "args": ["run", "C:/path/to/WhiskerWood_MCP/src/stdio.ts"],
      "env": { "WWMCP_CONFIG": "C:/path/to/WhiskerWood_MCP/wwmcp.config.json" }
    }
  }
}
```

## 8. Проверка

```bash
bun run doctor
```

Всё зелёное — запустите игру и спросите ассистента `ww_game_status`: он должен ответить
`status: running` с живым heartbeat моста.

## Что делать после патча игры

Игра обновилась — индекс устарел, и почти все инструменты начнут отказываться работать,
пока профиль не совпадёт с версией игры. В Claude Code — скилл `/ww-update-index`, он
проведёт через переиндексацию сам.

Готовый промпт на разбор поломавшихся модов после: `ww:fix-after-patch`.

Модам на Loom этого мало: они собираются против стабов кита, а не против игры. Разъехались
ли стабы с патчем — покажет `ww_loom_status`; обновление кита делает человек (стабы едут из
патча кита, в редакторе их не пересобрать), после чего нужна сборка Blueprint в редакторе,
чтобы обновить `types.json`. Сборка против старых стабов проходит без ошибок и ломается уже
у игрока.

## Типовые грабли

**`setup` падает с «каталог занят»** — профиль держит запущенный MCP-сервер, Windows не
даёт подменить каталог. Остановите сервер (в Claude Code — `/mcp`, перезапуск
`whiskerwood`) и повторите с `--force`. Действующий профиль при этом не страдает.

**Таблицы пустые, ошибок нет** — дампы от прошлой версии игры. См. раздел выше.

**Мод загрузился, но ничего не делает** — почти всегда неверный `hook_path`. Берите его
буквально из `ww_get_function` или `ww_verify_hook`, не собирайте руками: у нативных
функций форма `/Script/Pkg.Class:Func`, у блюпринтовых `/Game/Path/Asset.Asset_C:Func`.

**`require("ww.hook")` не находится** — библиотека не связана с `Mods/shared`. Лечится
`bun run bridge:deploy`.

**Хуки не встают на холодном старте** — блюпринтовых классов ещё нет в момент загрузки
`mods.txt`. Ставьте хуки только через `require("ww.hook").for_mod(MOD, log)`: он
дорегистрирует их после загрузки карты. Голый `RegisterHook` там бросает ошибку и обрывает
весь `main.lua`.

**Junction не создаётся** — нет прав на символические ссылки; `bridge:deploy` тогда молча
копирует файлы вместо линковки. Работать будет, но правки в репозитории не будут
подхватываться игрой без повторного `bridge:deploy`.
