# Устройство

Два независимых контура: медленный BUILD собирает индекс из файлов игры, быстрый READ
отвечает модели из готового индекса. Плюс мост в запущенную игру — третий, живой.

```
┌─ BUILD (минуты, редко) ──────────────────────────────────────────────┐
│  игра + AutoDump ──► ue4ss/{ObjectDump, UHTHeaderDump, *.usmap}      │
│         │                                                            │
│  bun run dumps:pull ──► dumps/  (+ wwpak.py вынимает AssetRegistry)  │
│         │                                                            │
│  bun run setup                                                       │
│    ├─ отпечаток игры (ProjectVersion из пака + sha256 exe)           │
│    ├─ index-reflection : ObjectDump + UHT + usmap ──► SQLite         │
│    ├─ index-gamedata   : сайдкар WwParse (CUE4Parse) ──► SQLite      │
│    ├─ приёмочные проверки                                            │
│    └─ атомарная публикация dist/games/whiskerwood-<версия>/          │
└──────────────────────────────────────────────────────────────────────┘
                              ↓
┌─ READ (миллисекунды, интерактивно) ──────────────────────────────────┐
│  MCP stdio ──► 30 инструментов ──► index.db (readonly) + memory.db   │
└──────────────────────────────────────────────────────────────────────┘
                              ↕ (живые инструменты)
┌─ МОСТ ───────────────────────────────────────────────────────────────┐
│  сервер ⇄ файлы в state/bridge/ ⇄ WWBridge (Lua в процессе игры)     │
└──────────────────────────────────────────────────────────────────────┘
```

## Почему так

**Индекс отделён от сервера.** Разбор 200 тысяч объектов занимает минуты, а модель ждать
не может. Профиль собирается заранее и публикуется атомарно: пока новый не прошёл
приёмочные проверки, действующий остаётся в силе.

**Профиль привязан к версии игры.** `profile.json` хранит `gameVersion`, и инструменты
отказываются отвечать, если он разошёлся с установленной игрой. Молча отдать данные от
прошлой версии хуже, чем отказаться: сигнатуры меняются, и мод сломается уже у игрока.

**Дампы сверяются с mtime пака.** `.usmap` от прошлой версии не вызывает ошибок — таблицы
с изменившимся layout просто отдают ноль строк. Это самый дорогой из известных способов
потерять день, поэтому сборка на таких дампах останавливается.

**Типы приходят из трёх источников.** UHT-заголовки дают настоящие C++ сигнатуры,
ObjectDump — раскладку в памяти, `.usmap` — енумы и типы полей. Каждое поле в ответе несёт
пометку, откуда взят его тип.

## Мост

UE4SS не даёт сокетов, поэтому канал файловый: сервер кладёт запрос в `state/bridge/`,
Lua-мод `WWBridge` опрашивает каталог каждые 120 мс, исполняет и пишет ответ. Он же держит
heartbeat, по которому `ww_game_status` отличает «игра закрыта» от «мост не установлен».

Через мост работают `ww_game_eval`, `ww_ui_tree`, `ww_deploy_mod`, `ww_screenshot`,
`ww_trace_calls` и `ww_game_console`. Всё остальное — чистое чтение индекса и работает без
запущенной игры.

Горячая перезагрузка мода сбрасывает `package.loaded["ww.*"]`, но снять подписки
`RegisterLoadMapPostHook` и `NotifyOnNewObject` нечем — поэтому состояние библиотеки
`ww.*` живёт в `_G`, а не в модулях.

## Каталоги

| | |
|---|---|
| `src/tools/` | по файлу на MCP-инструмент |
| `src/scripts/` | BUILD-контур: `setup`, `dumps:pull`, `doctor`, `bridge:deploy`, память |
| `src/utils/` | индекс, мост, песочница путей, отпечаток игры, работа с UE4SS |
| `bridge/` | Lua-моды: `WWBridge` (канал) и `AutoDump` (снятие дампов) |
| `data/lib/ww/` | рантайм-библиотека модов, линкуется в `ue4ss/Mods/shared` |
| `data/templates/` | шаблоны `ww_scaffold_mod` |
| `sidecar/WwParse/` | C#-сайдкар на CUE4Parse: читает таблицы данных по `.usmap` |
| `dumps/`, `dist/`, `state/` | не в гите: входы сборки, профили, рабочее состояние |

## Границы

Сервер пишет только в песочницу: репозиторий модов, `state/` и `dist/`. Единственное
исключение — `ww_extract_asset` с явным `dest_dir`. Сборку индекса модель запустить не
может: среди инструментов нет и не будет триггера BUILD — это ручной шаг человека.
