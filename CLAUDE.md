Отвечай на языке пользователя.

Это репозиторий MCP-сервера для моддинга игры Whiskerwood (UE 5.8). Моды пишутся на Loom
(`.lm` → Blueprint → `.pak` через мод-кит), UE4SS и сервер остаются для разведки игры и живой
отладки; Lua-моды под UE4SS — прежний путь, его инструменты в группе `lua`.
Устройство — `docs/ARCHITECTURE.md`, инструменты — `docs/TOOLS.md`, пайплайн Loom —
`docs/LOOM-PIPELINE.md`, план и замеры Loom-части — `docs/PLAN-loom.md`.

Правила для кода:
- не оставлять комментарии, только если очень надо в неочевидном месте и буквально несколько слов
- не пишем тесты
- проверка перед сдачей: `bun run typecheck`, `bun run doctor`, а при правке инструментов,
  промптов или ресурсов — `bun run smoke` (счётчики он берёт из `src/toolsets.ts`)
- внешние программы (`loom.exe`, редактор, RunUAT, UnrealPak) запускаются только через
  `src/utils/loom.ts`, долгие операции — джобами `src/utils/jobs.ts`, пути кита — из `src/utils/kit.ts`
- сервер пишет только в свои зоны (раздел «Границы» в ARCHITECTURE.md); новая зона записи —
  отдельный `PathSandbox` и правка этого раздела

MCP-сервер сессии запущен на коде, который был при её старте: новый или изменённый инструмент
проверяй обвязкой (`createServer` + `InMemoryTransport`, как в `src/scripts/smoke-client.ts`),
временные скрипты клади в скретч, а не в `state/`. Пересборка того же профиля индекса —
`ww_index_release`, затем `bun run setup --force`.

Знание об игре живёт в памяти сервера, а не в этом файле: до разведки — `ww_memory_search`
и `ww_lua_api`, после работы — `ww_memory_add`. Перечни инструментов и факты про отдельные
моды сюда не дублируем.

Общая база знаний (`data/memory-seed.jsonl`) правится не руками, а через
`bun run memory:export`. Личные пути вычищает санитайзер экспорта, записи с названиями модов
исключаются через `data/memory-seed.exclude.txt` — см. `docs/MEMORY.md`.
