# Переиндексация после патча игры

Индекс собирается из дампов, снятых изнутри конкретной версии игры. После патча дампы
и профиль устаревают: `.usmap` со старым layout ломает разбор молча — таблицы отдают ноль
строк без единой ошибки. Здесь только пересборка индекса. Разбор того, что сломалось в
модах — отдельный шаг, промпт `ww:fix-after-patch`, в конце сюда и отправишь.

Тебе уже доступны инструменты `ww_*` — MCP подключён. Если это не так (например, скилл
запущен сразу после клонирования репозитория, а не после патча) — это на самом деле
`/ww-setup`, не этот скилл.

## Как вести себя

- Если тебя привёл сюда промпт `ww:fix-after-patch` — согласие человека уже получено
  (он и есть повод, по которому скилл вызван). Не спрашивай второй раз, просто веди по
  фазам.
- Один шаг за раз, после каждой фазы — проверка, что она реально удалась, а не «наверное
  сработало».
- Запуск игры и загрузка сейва — не тихая операция: если игра уже открыта с непонятным
  прогрессом, предупреди, что загрузка сейва его заменит, и дождись подтверждения именно
  на этот шаг.
- Не изобретай ручной путь через AutoDump, пока `ww_capture_dumps` не отказал явно —
  тул существует ровно чтобы не гонять человека по mods.txt.

## Фаза 1. Подтвердить, что переиндексация вообще нужна

```
ww_index_status
```

Если профиль уже совпадает с версией игры и fingerprint fresh — сюда попали зря, скажи
об этом и останавливайся. Иначе запомни старую версию (пригодится для `ww_diff_versions`
в конце) и новую версию игры из ответа.

```
ww_memory_wakeup
```

Что уже известно про эту игру и прошлые патчи — может подсказать типовые грабли заранее.

## Фаза 2. Игра в загруженном мире

```
ww_game_status
```

- Не запущена → `ww_game_process action=start save=<сейв> wait_for=world`. Имя сейва
  спроси у человека либо возьми свежайший из `action=list_saves`.
- Запущена, но не в мире (главное меню) → `ww_game_process action=load_save
  save=<сейв> wait_for=world`.
- Запущена и уже в мире → ничего не делай, это и есть готовое состояние.

Дамп обязан сниматься из загруженного мира: блюпринтовые UI-классы подгружаются вместе
с картой, дамп из меню соберётся без единой ошибки, но половина этих классов в него не
попадёт и хуки на них потом не найдутся.

## Фаза 3. Снять дампы

```
ww_capture_dumps
```

По умолчанию выдерживает 60 секунд после входа в уровень (миру нужно время догрузить
объекты), потом сам снимает `.usmap`, `UE4SS_ObjectDump.txt`, `UHTHeaderDump` и проверяет
маркер `ALL DONE` в логе.

Разбери статус:

- `ok` → фаза 4.
- `no_world` → вернись к фазе 2, мир не загружен.
- `game_not_running` → игра закрылась между фазами, вернись к фазе 2.
- `timeout` или `marker_without_files` → посмотри `hint` в ответе и лог
  (`ww_game_log`); обычно достаточно повторить с большим `timeout_ms`. Если мост вообще
  не отвечает несколько попыток подряд — тогда, и только тогда, ручной путь: `AutoDump : 1`
  в `ue4ss/Mods/mods.txt` → зайти в сохранение → дождаться `ALL DONE captured_at=in_level`
  в `UE4SS.log` → закрыть игру → вернуть `AutoDump : 0`.

## Фаза 4. Забрать дампы и пересобрать индекс

Из Bash, не из MCP-инструментов — сборка индекса не инструмент сервера:

```bash
bun run dumps:pull
bun run setup
```

Прочитай вывод `setup` целиком: приёмочные проверки (`SetResearchTopic`, `TechUnlocksV2`,
`mod.desc.starvation [Ru]` и другие) должны пройти — если хоть одна упала, `setup`
не публикует профиль и оставляет черновик в `dist/games/.staging-*`, старый профиль
остаётся действующим. Это не поломка установки, а расхождение индекса с ожиданиями —
покажи человеку, какая именно проверка не прошла.

Если `setup` падает с «каталог занят» (бывает только при пересборке той же версии,
например повторный прогон после неполных дампов) — `ww_index_release`, затем
`bun run setup --force`.

Если в выводе упомянуты конфликты общей базы знаний — `bun run memory:sync`.

## Фаза 5. Проверить и передать эстафету

```
ww_index_status
```

Версия профиля должна совпасть с версией игры. `bun run doctor` — для полной сверки
заодно с остальным стендом.

Версию игры в релизах модов отсюда не трогай. `ww_package_mod` берёт её из действующего
профиля: с новым профилем следующая упаковка сама запишет версию в `mod.json` и в
строку требований УСТАНОВКА.txt/INSTALL.txt. Поэтому `game_version` в `mod.json` руками
не поднимают. Пока профиль устаревший, упаковка оставляет старую версию и предупреждает
в поле `game_version_source`.

Подведи итог: с какой версии на какую переиндексировались, откуда снят дамп
(`in_level`/`main_menu`), прошли ли приёмочные проверки. Дальше — разбор модов, промпт
`ww:fix-after-patch`.
