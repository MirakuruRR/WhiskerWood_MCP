# Разворачивание Whiskerwood MCP

Ты проводишь человека через установку. Вся детерминированная логика уже в скриптах
(`doctor`, `bridge:deploy`, `dumps:pull`, `setup`) — твоя работа не дублировать их, а
запускать, читать вывод, чинить типовые поломки и вести через шаги, которые скрипт
сделать не может.

**MCP-сервер на этом этапе ещё не подключён.** Инструменты `ww_*` тебе недоступны до
фазы 5. Работай через Bash.

## Как вести себя

- Один шаг за раз. После каждой фазы — `bun run doctor` и разбор того, что он сказал.
- Не выдумывай пути и версии: всё берётся из вывода `doctor`.
- Фазу 2 человек делает руками — установка UE4SS. Дай точную инструкцию, дождись
  подтверждения, проверь результат сам — не считай сделанным со слов. Тот же принцип
  для фазы 6, если там придётся уйти на ручной путь.
- Если `doctor` показывает `ok` по фазе — пропусти её. Скилл идемпотентен, повторный
  запуск не должен ничего ломать.
- Не запускай `bridge:deploy`, пока игра запущена: он пересоздаёт каталоги в `Mods/`.
  Проверь `tasklist | grep -i whiskerwood`.

## Фаза 0. Что уже есть

```bash
bun install
bun run doctor
```

`doctor` — единственный источник истины о состоянии стенда. Прочитай вывод целиком и
составь план: какие фазы ниже уже закрыты, какие нет. Скажи человеку, что предстоит
сделать руками (обычно это установка UE4SS), чтобы он понимал объём.

## Фаза 1. Тулчейн

Нужны `bun`, `python` 3, `.NET SDK 10`. Если чего-то нет — дай ссылку и дождись установки:

- Python: https://www.python.org/downloads/ (галка «Add to PATH»)
- .NET SDK 10: https://dotnet.microsoft.com/download

Нужен именно SDK, а не Runtime: сайдкар собирается из исходников.

## Фаза 2. Игра и UE4SS (руками)

`doctor` находит игру через Steam сам. Если не нашёл — спроси путь.

UE4SS ставится вручную: скачать 3.0.1 с https://github.com/UE4SS-RE/RE-UE4SS/releases и
распаковать в `<игра>/Whiskerwood/Binaries/Win64` так, чтобы рядом с
`Whiskerwood-Win64-Shipping.exe` лёг `dwmapi.dll`, а рядом — каталог `ue4ss/`.

Потом человек запускает игру один раз и закрывает — чтобы появился `ue4ss/UE4SS.log`.
Проверь, что файл есть, и назови определившуюся версию.

## Фаза 3. Конфигурация

```bash
cp wwmcp.config.example.json wwmcp.config.json
```

Если `doctor` нашёл игру и путь совпал — править нечего. Если нет — поправь `gameDir`,
остальное раскроется из него.

Спроси, где человек будет держать моды, и пропиши в `modsRepo`. По умолчанию это
`../WhiskerWood_Mods` рядом с этим репозиторием; отсутствующий каталог создастся сам.
Библиотека `ww.*` приезжает из `data/lib/` этого репозитория, так что пустой каталог
модов — полноценный вариант.

Спроси путь к мод-киту Whiskerwood, если человек собирается делать моды на Loom
(репозиторий `Whiskerwood-Project`, ветка 5.8 — каталог с `.uproject`), и пропиши его в
`kitDir`. Кит необязателен: без него всё, кроме Loom-инструментов, работает как раньше,
а Loom-инструменты отвечают `kit_not_configured` со ссылкой на этот скилл — это не
ошибка стенда, а незаданный ключ.

Движок отдельно указывать не надо: он находится сам по `EngineAssociation` из
`<кит>/Whiskerwood.uproject` через реестр (`HKCU\Software\Epic Games\Unreal Engine\Builds`).
`engineDir` — только ручной override, когда сборка движка лежит не там, где записано в
реестре.

```bash
bun run doctor
```

Секция Loom в выводе — единственный источник истины и здесь: `loom.exe`, `types.json`,
`UnrealEditor-Cmd.exe`, `UnrealPak.exe`, `RunUAT.bat`, открыт ли редактор, не отстал ли
`types.json` от пака игры. Чего может не быть и почему:

- `loom.exe` — в ките нет собранного плагина `LoomEditor`: нужен кит с собранными бинарями;
- `types.json` — в ките ещё ни разу не собирали Blueprint: он появляется после первой
  сборки в редакторе (`Tools › Rebuild All Blueprints` или LoomBuild);
- движок — GUID из `EngineAssociation` не найден в реестре: спроси путь и впиши `engineDir`.

## Фаза 4. Мост

```bash
bun run bridge:deploy
```

Ставит WWBridge (включён), AutoDump (выключен) и линкует библиотеку в `Mods/shared`.
Убедись по выводу, что все три строки прошли. `mods.txt: оставлен как есть` для AutoDump —
это норма, значит запись уже была.

## Фаза 5. Подключение MCP

В Claude Code `.mcp.json` уже лежит в репозитории. Скажи человеку перезапустить клиент,
чтобы сервер подхватился, и дождись возвращения.

Но этот файл работает только в сессии, открытой в самом репозитории, и путь в нём
относительный: сессия, открытая в ките или в репозитории модов, сервера не видит. Поэтому
предложи зарегистрировать сервер на пользовательском уровне — в `~/.claude.json`
(`%USERPROFILE%\.claude.json`), в `mcpServers`, рядом с уже живущим там `loom`. Пути
абсолютные, `WWMCP_CONFIG` обязателен: без него сервер ищет `wwmcp.config.json` в текущем
каталоге сессии.

```json
"whiskerwood": {
  "type": "stdio",
  "command": "C:/Users/<пользователь>/.bun/bin/bun.exe",
  "args": ["run", "D:/WhiskerWood_MCP/src/stdio.ts"],
  "env": { "WWMCP_CONFIG": "D:/WhiskerWood_MCP/wwmcp.config.json" }
}
```

Правь файл аккуратно: это JSON, и лишняя запятая сломает клиенту весь список серверов.
Путь к `bun.exe` возьми свой (`where bun`), а не из примера. После правки нужен перезапуск
клиента — `~/.claude.json` читается один раз при старте. Проверь, что поднялись оба
сервера: в `/mcp` должны быть и `whiskerwood`, и `loom`.

Если моды в отдельном репозитории — можно и там создать `.mcp.json` с абсолютными путями до
`src/stdio.ts` и `wwmcp.config.json` (шаблон в `docs/SETUP.md`, раздел 7).

Дампов и индекса ещё нет — почти все инструменты `ww_*` откажут ссылкой на это. Живые же
(`ww_game_status`, `ww_game_process`, `ww_capture_dumps`, `ww_game_log`, ...) работают и
без индекса — они сейчас и понадобятся.

## Фаза 6. Дампы

Раньше это был обязательный ручной шаг — теперь его делает `ww_capture_dumps` через живой
мост, без AutoDump и без лишнего перезапуска игры.

1. Убедись, что игра запущена и загружен мир: `ww_game_status`. Если нет —
   `ww_game_process action=start save=<имя сейва> wait_for=world` (имя сейва — из
   `action=list_saves`, если человек не назвал; сойдёт и `_autosave`).
2. `ww_capture_dumps`. По умолчанию выдерживает 60 секунд после входа в уровень (миру
   нужно время догрузить объекты), потом снимает `.usmap`, `UE4SS_ObjectDump.txt`,
   `UHTHeaderDump` и сама проверяет маркер `ALL DONE` в логе. `status: ok` — дальше.
3. `status: no_world` — сейв не загружен, вернись к шагу 1.
4. `status: game_not_running`, либо мост вообще не поднялся (`ww_game_status` не видит
   heartbeat) — переходи на ручной путь: `AutoDump : 1` в `ue4ss/Mods/mods.txt` → запустить
   игру → зайти в сохранение → дождаться в `UE4SS.log` строки
   `ALL DONE captured_at=in_level` (~60 секунд, либо горячая клавиша `Ctrl+Alt+F9`) →
   закрыть игру → вернуть `AutoDump : 0`.

Потом в любом случае:

```bash
bun run dumps:pull
```

## Фаза 7. Сборка индекса

```bash
bun run setup
```

Идёт минуты. Заодно вливает общую базу знаний — скажи, сколько записей приехало.

Если упало — смотри `references/troubleshooting.md`, там разобраны все известные отказы
этого шага.

## Фаза 8. Живая проверка

Проверь связку целиком:

1. `ww_index_status` — профиль совпадает с версией игры
2. `ww_game_status` — должно быть `status: running` с живым heartbeat (игра всё ещё
   открыта с фазы 6, либо запроси её снова)
3. `ww_memory_wakeup` — общая база на месте

Подведи итог: что установлено, какая версия игры и UE4SS, сколько записей в памяти, где
лежат моды. Дальше человеку нужен промпт `ww:new-mod` — назови его. Если он собирается
делать моды на Loom (кит настроен), назови `ww:new-loom-mod` и скажи, что в этом режиме
набор `lua` из `toolsets` убирают, а инструкция с примером лежит в `docs/SETUP.md`, раздел 6.

## Если что-то пошло не так

`references/troubleshooting.md` — известные отказы и их причины. Читай оттуда, не
изобретай диагноз заново.
